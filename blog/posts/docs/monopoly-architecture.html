大富翁 Online — 技术架构

版本 v0.1 · 状态：草稿 · 关联 PRD：monopoly-prd.html

定义游戏的技术架构：组件结构、状态管理、数据模型、渲染方案、Bot 决策状态机。

1. 技术栈

层技术说明
渲染Canvas 2D环形棋盘渲染、玩家令牌移动动画、骰子动画、卡片动画
UI布局HTML + CSS Grid/Flex玩家面板、弹窗（买地/租金/机会卡）、按钮操作区
逻辑原生 JS（ES6+）无框架依赖，单文件约 1500-2000 行
棋盘渲染DOM + CSS 绝对定位40 格矩形环形布局（4 边各 10 格），用 top/left/right/bottom 定位绕圈。格子是 div，点击天然有事件，无需 hit-testing。
令牌动画CSS transition令牌是 div，用 transform: translate() + transition: 0.3s ease 实现跨格平滑移动。
骰子/卡片动画CSS @keyframes + JS骰子抖动 / 卡片滑入均用 CSS @keyframes，JS 控制时序和显示。
弹窗/面板HTML + CSS买地弹窗、租金弹窗、玩家资产面板 — 纯 HTML/CSS 显示/隐藏。
游戏逻辑原生 JS（ES6+）无框架依赖，单文件约 1500-2000 行。
部署单文件 HTML无构建步骤，所有 HTML/CSS/JS 内联，直接丢到 GitHub Pages。

为什么不用 Canvas？棋盘是静态的（40 格位置固定），令牌是"跳格"的（不是沿曲线连续移动），用 DOM 可以天然获得格子点击事件，无需手动计算 hit-testing。CSS transition 已经足够处理回合制跳格动画。只有在做令牌沿环形轨道平滑滑动时才考虑 Canvas，必要性不高。

3. 组件结构

整体采用 MVC 模式，所有代码内联于单个 HTML 文件。

模块职责关键函数

🗺️ BoardRendererDOM 布局环形棋盘（40格 div）、玩家令牌定位、格子高亮状态initBoard(), moveToken(), highlightCell()
📊 UIPanel玩家资产面板、回合指示、按钮操作区updatePanel(), showModal(), hideModal()
🤖 BotAIBot 决策执行、思考动画、策略参数decide(), executeAction(), showThinking()

4. 游戏主流程

游戏启动 → setup() [初始化棋盘、玩家、金币、卡牌]
    ↓
startTurn(player) [玩家回合开始]
    ↓
roll() → 显示骰子动画 → 获得点数
    ↓
检查 isDouble → true: 可继续掷 | false: 结束回合
    ↓
移动令牌 → animateMove() → 到达目标格
    ↓
触发格子的效果（switch cell.type）:
  land:     有主? → payRent() : buyPrompt()
  chance:   CardDeck.draw('chance') → 执行效果
  fate:     CardDeck.draw('fate') → 执行效果
  station:  payStationRent()
  airport:  teleportPrompt() [玩家选择目标]
  jail:     检查 inJail ? → 保释/掷双骰 : 正常路过
  start:    awardStartMoney()
  park:     无事发生
    ↓
endTurn() [切换到下一玩家]
    ↓
检查胜利条件 → 所有对手破产? 或 回合=20? → endGame()
    ↓
若无胜利 → startTurn(下一玩家)

5. Bot 决策状态机

Bot 回合开始
    ↓
状态: IDLE
    ├─ 等待 0.5-1.5 秒（思考动画）
    ↓
状态: DECIDING
    │
    ├─ 阶段A：是否买地?
    │   计算: 资金 > 地价 × 买地意愿阈值?
    │   鹰: 0.6 | 龟: 1.2 | 狐: 0.9
    │   → 买 → BIDDING
    │   → 不买 → 阶段B
    │
    ├─ 阶段B：是否升级?
    │   计算: 资金 > 盖房费 × 升级意愿阈值?
    │   鹰: 0.8 | 龟: 1.5 | 狐: 1.0
    │   → 升级 → UPGRADING
    │   → 不升级 → 阶段C
    │
    └─ 阶段C：是否交易?
        狐Bot 专属（交易接受度高）
        评估当前提案，接受/还价/拒绝
    
状态: EXECUTING
    ├─ 执行决策（买地/升级/交易）
    ├─ 显示 Bot 思考日志（"狐狸Bot 购买了上海地块"）
    └─ 更新 UI
    
状态: WAITING
    └─ Bot 回合结束，切换下一玩家

注意: Easy 模式下，阶段A/B 各有 30-40% 概率故意做出次优决策

6. 棋盘 DOM 布局

容器: #board { position: relative; width: 860px; height: 620px; }

┌─────────────────────────────────────────────────────┐ ← top
│  1(起点)  2   3   4   5   6   7   8   9  10         │
│  40                                           11     │ ← left / right
│  39                                           12     │
│  38                                           13     │
│  37                                           14(停车)│
│  36                                           15     │
│  35                                           16     │
│  34(命运)                                     17     │
│  33                                           18(机会)│
│  32(机场) 31(监狱) 30  29(机会) 28  27  26  25  24  23│ ← bottom
└─────────────────────────────────────────────────────┘

定位方式:
  北边(1-10):     position=absolute; top=0;    left逐步增加
  东边(11-20):    position=absolute; right=0;  top逐步增加
  南边(21-30):    position=absolute; bottom=0; right逐步增加（逆序）
  西边(31-40):    position=absolute; left=0;    bottom逐步增加（逆序）

每个格子: .cell { position: absolute; width: 60px; height: 50px; border: 1px solid var(--border); }
令牌容器: .token { position: absolute; width: 20px; height: 20px; border-radius: 50%;
                  transition: transform 0.3s ease; }

Canvas 尺寸建议: 棋盘区域 860×620px，总 UI 区域（含左右面板）约 1200×700px。适合 1080p 屏幕。

10. 实现优先级（Phase 1 MVP）

P0 — 核心循环
骰子 → 移动 → 落地判定 → 买地/付租 → 结束回合。2个Bot（鹰+龟），4格环形地图测试版。
P1 — 完整棋盘
40格完整城市地图，Canvas 渲染环形棋盘，3个Bot（鹰+龟+狐），全部卡牌。
P2 — UI 打磨
玩家面板、弹窗系统、所有动画（骰子/移动/卡片/租金）、Bot 思考日志。
P3 — 特殊格
机场传送、监狱禁足、起点奖励、竞拍机制、交易系统。
Recommended Next Step：从 P0 开始，先做 4 格测试版验证核心循环正确，再逐步扩展到完整 40 格。
