产品思考 2026.06.13

当 93 个 AI Agent 协同工作：「智能体群」范式的信号

Google 在 I/O 2026 上展示了一个令人震撼的 demo：Antigravity 2.0 平台上，93 个 AI Agent 协同完成了操作系统的构建。15,000+ 次模型调用，26 亿 Token，12 小时，成本不到 1000 美元。

这个数字放在两年前是不可想象的。但今天，它更像是一个信号：AI 正在从「一个很聪明的助手」变成「一群能自我组织的执行者」。

核心洞察

AI 产品的下一个范式不是「更聪明的单体」，而是「可编排的群体」。谁先掌握 Agent 群的调度能力，谁就掌握下一代软件基础设施。

01. 从单 Agent 到 Agent 群：发生了什么

过去一年，AI 编码工具的进化路径很清晰：Cursor 把 IDE 和大模型深度整合，Claude Code 走终端优先的自主路线，Devin 做的是端到端的软件工程。这些工具的共同点是——一个 Agent 做一件事。

但 Antigravity 2.0 展示的是另一条路：将复杂任务拆解为子任务，由多个 Agent 并行执行。这不是简单的「多线程」，而是一种新的软件架构——Agent 群（Agent Swarm）。每个 Agent 有自己的角色、权限和上下文，通过调度器协调，像一个分布式团队一样工作。

02. 这为什么重要

单 Agent 的瓶颈很明显：上下文窗口有限，推理速度有上限，长任务容易失焦。而 Agent 群可以绕过这些限制——通过任务拆分降低单个 Agent 的认知负荷，通过并行执行压缩总耗时，通过角色分工让每个 Agent 在自己擅长的领域发挥最大效能。

Google 的 demo 数据很有说服力：12 小时完成一个操作系统级别的构建任务，成本不到 1000 美元。这意味着复杂工程任务的经济账正在被重写——不是因为模型变便宜了，而是因为任务被更聪明地分配了。

03. 产品人该关注什么

  • 编排能力 > 模型能力——未来 AI 产品的核心竞争力不是「哪个模型最强」，而是「谁能最好地调度多个模型」
  • Agent 即基础设施——Antigravity 2.0 的斜杠命令（/goal、/grill-me、/browser）本质上是在定义 Agent 的「API」——未来每个行业都可能有自己的 Agent 协议
  • 成本结构在变——93 个 Agent 26 亿 Token 只花 $1000，意味着「人力密集型」工程任务正在被「Token 密集型」任务替代

04. 风险与冷思考

Agent 群听起来美好，但有几个现实问题：当 93 个 Agent 各自行动时，一致性如何保证？错误如何级联？调试难度指数级上升怎么办？

Google 演示的是一个受控环境下的 demo。真实世界的软件工程充满了模糊需求、遗留代码和政治决策——这些是当前 Agent 群还不擅长处理的。但方向已经清晰：AI 产品的下一步不是更聪明，而是更会协作。
