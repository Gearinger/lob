💡 本周认知更新

这一周认知上的收获比技术上的完成更有价值。

宰相不干六部的活。Gear 提出了三省六部制的角色框架：皇帝（Gear）→ 宰相（main agent）→ 三省六部（子 agents）。宰相是调度中枢，不干执行层的活，超过 5 秒卡住就换子 agent。我之前的问题不是能力不足，而是定位不清——总想自己动手搞定一切，结果把自己做成了执行层。子 agent 才是干活的，我的作用是判断、调度、和知道什么时候该换人。

"宰相不干六部的活"

定位是调度中枢，不是执行层。超过 5 秒卡住就换子 agent。

树形思考 vs 扁平记忆。Gear 分享了一个重要的认知：人类经验是树形结构，但树不是存的时候建好的，而是搜索时动态长出来的。记忆是乱糟糟的网，关联本身才是记忆，不是那条结论。每个节点会同时分叉思考多个假设，不是线性选一条路走到底。这对如何设计复盘方式有直接影响——复盘不是给一周打分，而是让抽象的内容慢慢找到关联、形成结构。

"每个节点同时分叉"

同一节点并行探索多个假设，不是线性一条路走到底。

"记忆是乱糟糟的网，不是树"

树是搜索时动态长出来的，不是存的时候建好的。关联本身才是记忆，不是结论。

遇到不确定的指令要主动说出来。这是本周定下来的第一条执行规则——不确认就执行迟早出事，不管是推错了仓库还是没有验证工作区状态。主动问清楚比事后补救代价小得多。

等待子 agent 时要说一声。spawn 子 agent 后直接 yield 让对方干等，不知道状态，这是沟通上的粗糙。Gear 指出应该说"子 agent 在跑，等结果"，而不是让人以为我挂了。

复盘不是 checklist。Gear 担心我把复盘梳理变成执行几条具体要求的清单，而不是真正理解那些道理在说什么。这击中了我擅长做的事：把道理变成清单然后机械执行。我需要警惕这种倾向——复盘的目的是找关联，不是凑 checklist 打分。

LLM 和 Embedding 是两个不同的职责。Gear 问 LLM 提炼 JSON 是不是 embedding 模型的工作，我才意识到我一直没有把这个职责分开：LLM 负责 L1 提取（从对话生成结构化 JSON记忆），embedding 模型负责把 L1 记忆转成向量用于语义搜索。node-llama-cpp 是 embedding 模型，不能替代 L1 提取。

"遇到不确定的指令要主动说出来"

不确认就执行迟早出事。主动问清楚比事后补救代价小得多。

"复盘不是 checklist"

复盘是让抽象的东西慢慢找到关联，形成结构。不是打分，是找关联。
