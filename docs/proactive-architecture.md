# Proactive Agent Architecture — 主动思维 Agent 系统方案

*Created: 2026-05-01 | Author: Lob*

---

## 1. 问题定义

Lob（当前 agent）存在**被动响应**的问题：等指令，不主动思考。表现为：

- 每次改完代码，只检查报错，不截图看效果
- 解决问题后不追问"有没有连带问题"
- 不主动回顾"还有什么悬着"

**根因**：没有建立主动思维的习惯和机制，不是模型能力不足。

---

## 2. 核心设计原则

1. **规则模式 > 清单模式** — 3条规则覆盖所有文件类型，不用逐个记录文件
2. **机制替代习惯** — 不是靠外部提醒，是内化成思维的一部分
3. **抽象到行为层，不记录具体** — "改完 CSS 触发验证思考"而不是记录每个文件
4. **Layer 1 是思维习惯，不是触发器** — 同步发生，自然融入每次思考

---

## 3. 三层架构

```
┌─────────────────────────────────────────────────┐
│  Layer 1: 思维习惯（同步，实时追问）               │
│  每次产生"完成感"时，自动触发4问                  │
├─────────────────────────────────────────────────┤
│  Layer 2: 状态维护（单一数据源）                   │
│  memory/tasks-and-issues.md                      │
├─────────────────────────────────────────────────┤
│  Layer 3: 主动思维（异步，sub-agent执行）         │
│  会话空闲时运行，结果推送tasks                    │
└─────────────────────────────────────────────────┘
```

---

## 4. Layer 1 — 思维习惯（4问）

每次产生"我完成了X"这个想法时，自动追问：

| 编号 | 问题 | 目的 |
|------|------|------|
| Q1 | X相关的还有什么？（文件/数据/逻辑） | 连带性检查 |
| Q2 | 谁会直接用这个？会有什么风险？ | 输出风险识别 |
| Q3 | 这个结论的前提假设是什么？ | 假设检验 |
| Q4 | 这个是某种已知错误模式的实例吗？ | 模式识别 |

**触发条件**（规则模式，不是清单）：
- 新增/修改 .css 文件
- 新增/修改 .html 文件
- 修改共享组件（header.js / colors.css）
- 修改设计规范文档
- 根据数据得出新结论
- 修改计算逻辑/处理管道

**可异步部分**：验证动作放后台执行，不阻塞主会话。

---

## 5. Layer 2 — 状态维护

**单一数据源**：`memory/tasks-and-issues.md`

**结构**：

```markdown
## 🔄 进行中
- [ ] 任务描述 | 来源 | 严重程度

## ⚠️ 待处理问题
| 问题 | 来源 | 严重程度 | 对应文件 |

## ✅ 已解决
| 问题 | 解决方案 | 日期 |
```

**更新时机**：
- 完成任何修复 → 立即更新
- 发现新问题 → 立即写入
- 每周复盘 → 扫一遍，处理过期项

**可异步**：定期批量归档（复盘时）。

---

## 6. Layer 3 — 主动思维（Sub-agent）

**触发时机**：主会话空闲时（没有活跃任务时）。

**任务流程**：
1. 读 `memory/tasks-and-issues.md`
2. 扫描"已解决"列表，找重复模式
3. 扫描"待处理"列表，预测潜在问题
4. 生成主动建议（"这个问题可能也会出现在X处"）
5. 建议写回 `tasks-and-issues.md`

**结果回传**：sub-agent 完成后，主会话下次启动时读到新建议。

**实现**：
```javascript
// 当主会话空闲时
if (hasNoActiveTask()) {
  spawnSubAgent({
    task: "proactive-analysis",
    runtime: "subagent",
    mode: "run"
  })
}
```

## 7. 针对不同领域的触发规则

### 7.1 UI/前端

**触发条件**：
- 新增/修改 .css 文件
- 新增/修改 .html 文件
- 修改共享组件（header.js / colors.css）

**验证方式**：截图渲染，对照设计规范。

### 7.2 数据分析

**触发条件**：
- 根据数据得出新结论/新数字之前
- 修改了计算逻辑/处理管道
- 给出了建议/决策依据

**验证方式**：
- 假设检验：这个结论的反例是什么？
- 数据来源交叉验证
- 结果敏感性分析：换个假设还成立吗？

**常见错误模式识别**：
- 样本偏差
- 因果推断错误
- 幸存者偏差
- 数字解读偏差

### 7.3 代码逻辑

**触发条件**：
- 修改了共享模块
- 重构/改写了核心逻辑

**验证方式**：
- 边界条件检查
- 依赖影响分析
